# Spec: Внедрение планирования и памяти (Reasoning & Memory)

## 1. Цель
Трансформировать поведение агента из реактивного в проактивное. Агент должен уметь разбивать сложные задачи на шаги, отслеживать выполнение плана и сохранять важную информацию между шагами.

## 2. Новые инструменты
### 2.1. Planning Tool
-   `update_plan(steps: list[str], current_step_index: int)`: Позволяет агенту создать или обновить список шагов для достижения цели.
    -   `steps`: Список строк, описывающих шаги.
    -   `current_step_index`: Индекс текущего выполняемого шага (0-based).

### 2.2. Memory Tool
-   `save_memory(key: str, value: str)`: Сохраняет факт или данные в кратковременную память сессии.
-   (Опционально) `read_memory(key: str)`: В рамках текущей архитектуры память передается в контексте, поэтому явный вызов `read` может не потребоваться, но инструмент для сохранения обязателен.

## 3. Изменения в архитектуре
-   **Context Management:** В класс `Agent` (или `Orchestrator`) нужно добавить управление состоянием `Plan` и `Memory`.
-   **System Prompt:** Обновить промпт, чтобы он включал текущее состояние плана и памяти в каждом запросе к модели.
-   **Reasoning Loop:** Модель должна быть поощрена сначала обновить план (если нужно), а затем выполнить действие.

## 4. Сценарий использования (User Flow)
User: "Сравни цены на iPhone 15 на Amazon и eBay".
Agent:
1.  Call `update_plan(["Go to Amazon", "Search iPhone 15", "Save price", "Go to eBay", "Search iPhone 15", "Save price", "Compare"], 0)`
2.  Action: `navigate(amazon)`
3.  ...
4.  Call `save_memory("amazon_price", "$999")`
5.  Call `update_plan(..., 3)` (Go to eBay)
...
