# Техническое Задание: Автономный AI-агент для управления браузером

## 1. Общее описание проекта

Разработка консольного приложения (CLI) с AI-агентом, способным выполнять многошаговые задачи в веб-браузере на основе команд на естественном языке. Агент управляет реальным браузером, визуально анализирует интерфейс (Vision capabilities) и взаимодействует с элементами DOM, эмулируя действия человека.

**Ключевая особенность:** Отсутствие хардкода селекторов. Агент динамически определяет элементы управления, используя возможности мультимодальной модели Gemini 2.0.

## 2. Технологический стек

* **Язык программирования:** Python 3.10+
* **AI Модель:** Gemini 2.0 Flash (Free Tier).
* **AI SDK:** `google-genai` (новая библиотека Google Gen AI SDK).
* **Браузерная автоматизация:** Playwright (Python).
* **Обработка изображений:** Pillow (PIL) — для оптимизации скриншотов перед отправкой.
* **Управление зависимостями/Среда:** `uv` или `poetry` (рекомендуется), либо `pip`.
* **Конфигурация:** `python-dotenv` (хранение `GEMINI_API_KEY`).

## 3. Требования к реализации

### 3.1. Архитектура агента (ReAct / Loop)

Агент должен работать в бесконечном цикле до выполнения задачи или ошибки:

1. **Observe (Наблюдение):** Снятие скриншота текущей страницы.
2. **Annotate (Разметка):** Внедрение JS-скрипта для нумерации интерактивных элементов (Set-of-Mark Prompting). Наложение визуальных меток (ID) на скриншот или DOM.
3. **Think (Анализ):** Отправка скриншота и контекста задачи в Gemini 2.0 Flash.
4. **Act (Действие):** Получение структурированного ответа (JSON) от модели с вызовом инструмента (Tool Call).
5. **Execute (Выполнение):** Исполнение действия через Playwright (клик, ввод текста, скролл).

### 3.2. Ключевые функции (Tools)

Агент должен иметь доступ к следующим инструментам (Function Calling):

* `click_element(label_id: int)`: Клик по элементу с указанным визуальным номером.
* `type_text(label_id: int, text: str)`: Ввод текста в поле.
* `scroll(direction: str, amount: str)`: Прокрутка страницы.
* `Maps(url: str)`: Переход по прямому URL (если модель решит, что это быстрее).
* `get_page_text()`: Извлечение текстового контента (для анализа писем/резюме).
* `ask_user(question: str)`: Запрос подтверждения (Security Layer) или уточнения у пользователя.
* `task_completed(result: str)`: Завершение работы с отчетом.

### 3.3. Пользовательские сценарии (Use Cases) из задания

Агент должен справляться с тремя базовыми сценариями:

#### Сценарий А: Удаление спама (Яндекс.Почта)

* **Вход:** Persistent Session (пользователь уже залогинен).
* **Действия:** Переход во "Входящие" -> Чтение списка -> Анализ тем/отправителей -> Выбор писем -> Удаление.
* **Security Layer:** Перед удалением агент должен спросить: *"Я нашел 3 спам-письма от 'SuperCasino'. Удалить их?"*

#### Сценарий Б: Заказ еды (Яндекс.Еда / Delivery)

* **Действия:** Поиск ресторана -> Выбор блюд (Бургер, Картошка) -> Добавление в корзину -> Переход к чекауту.
* **Ограничение:** Не нажимать финальную кнопку "Оплатить" (остановиться на проверке заказа).

#### Сценарий В: Поиск вакансий (HH.ru)

* **Действия:** Поиск "AI Engineer" -> Фильтрация -> Открытие вакансии -> Анализ соответствия (сравнение с резюме) -> Нажатие "Откликнуться" (с генерацией сопроводительного письма).

## 4. User Flow (Пользовательский путь)

1. **Запуск:** Пользователь запускает скрипт в терминале.
```bash
python main.py "Зайди в почту и удали письма от 'Рассылка Госуслуг' за сегодня"

```


2. **Инициализация:** Открывается окно браузера (Chrome/Chromium) with загруженным профилем пользователя (`user_data_dir`).
3. **Процесс:**
* В терминале отображаются логи ("Мысли агента"):
* `[AGENT] Вижу список писем. Ищу 'Рассылка Госуслуг'`.
* `[TOOL] Click element #45`.


* В браузере видны действия: курсор двигается (эмуляция), страницы переключаются.


4. **Взаимодействие:** Если задача критичная, агент выводит промпт в консоль: `[Confirm] Удалить письмо "Штраф ГИБДД"? (y/n)`.
5. **Завершение:** Агент закрывает браузер (или оставляет открытым по флагу) и выводит отчет: `[DONE] Успешно удалено 1 письмо.`

## 5. Детали реализации (Подсказки для разработки)

### 5.1. Работа с `google-genai`

Использовать клиент в режиме совместимости с OpenAI или нативный, но с поддержкой `GoogleSearch` (если нужно) и Vision.

Пример структуры вызова:

```python
from google import genai
from google.genai import types

client = genai.Client(api_key="GEMINI_API_KEY")

# Конфигурация инструментов
tools = [click_element, type_text, ...] 

response = client.models.generate_content(
    model="gemini-2.0-flash-exp", # Или актуальная версия
    contents=[
        types.Content(role="user", parts=[
            types.Part.from_text("Задача: " + user_prompt),
            types.Part.from_image(image_bytes)
        ])
    ],
    config=types.GenerateContentConfig(
        tools=tools,
        system_instruction="Ты — AI-агент, управляющий браузером. Твоя цель..."
    )
)

```

### 5.2. Визуальная разметка (Set-of-Mark)

Для корректного `click_element(id)` необходимо перед скриншотом инжектировать JS.

* **Задача JS:** Найти все интерактивные элементы (`a`, `button`, `input`), проверить `isVisible()`, присвоить каждому уникальный `data-agent-id` и нарисовать поверх полупрозрачный div с номером.
* **Задача Python:** Хранить словарь `{id: playwright_locator}`. Когда модель присылает `id=5`, скрипт ищет локатор с `data-agent-id="5"` и делает `.click()`.

### 5.3. Обработка ошибок (Self-Correction)

* Если Playwright выбрасывает `TimeoutError` или `ElementNotVisible`:
* Не падать!
* Передать ошибку обратно в Gemini: `ToolOutput: Error - element not clickable`.
* Gemini должна решить: попробовать другой элемент, проскроллить или изменить стратегию.

# AgentBrowser: Автономный AI-агент для управления браузером

## Обзор продукта
AgentBrowser — это консольное приложение (CLI), предназначенное для автоматизации рутинных задач в веб-браузере с использованием возможностей мультимодальной модели Gemini 2.0 Flash. Проект ориентирован на опытных пользователей, стремящихся повысить свою продуктивность за счет делегирования многошаговых веб-операций интеллектуальному агенту.

## Основная цель
Автоматизация повторяющихся процессов в вебе для повышения личной продуктивности пользователя, устраняя необходимость ручного взаимодействия со сложными или динамическими интерфейсами.

## Целевая аудитория
*   **Опытные пользователи:** Те, кто предпочитает работу в терминале и хочет автоматизировать свои повседневные задачи в интернете.

## Ключевые функции
*   **Автономная навигация:** Самостоятельное выполнение действий на веб-страницах (клик, ввод данных, прокрутка) на основе команд на естественном языке.
*   **Визуальный анализ (Vision):** Агент «видит» интерфейс страницы, распознает интерактивные элементы и понимает контекст без использования жестко заданных селекторов.
*   **Интерактивное выполнение (Security Layer):** Агент запрашивает подтверждение пользователя перед совершением критических действий (например, удаление данных или совершение оплаты).

## Решаемые проблемы
*   **Сложность автоматизации:** Устранение высокого порога входа (не требуется знание HTML/DOM для настройки скриптов).
*   **Динамические интерфейсы:** Решение проблемы «хрупких» селекторов — агент адаптируется к изменениям дизайна сайтов так же, как человек.
